# ivypath-humanize-zh · 中文对外内容语感与去 AI 味

读者是焦虑但聪明的申请者和家长。他们已经刷过一堆公众号，缺的不是信息量，是可信的判断。IvyPath 的声线因此是：克制、第一手、不 PUA；可以下判断（「编程弱的慎入」），不贩卖焦虑，不喊口号；每篇至少一处不完美信息（行业的风险、项目的短板、申请的坑），全是好话没人信。

这份 skill 把三条线拧在一起：白皮书、案例文、小红书三个生产线 skill 里各自维护的去 AI 味规则（原来三处阈值互相打架），七个去 AI 味 skill 里经过实测的规则（lieflat 的 11 条白名单和「不作为改写理由」表、qu-ai-wei 的八个模式族与信息账本、说人话的信息守恒、humanizer / stop-slop-zh 的词表），以及顾问改稿沉淀的用词 DNA。去掉的是会制造另一种模板的做法：强制塞 8–10 个口语词、全文禁用冒号、每篇必须「文化哲学升维」、给文章「注入情绪」。

## 一、铁律（改任何一个字之前先记住）

1. **信息守恒：不加事实。** 不新增数据、案例、学生、公司、课程、教授、时间、来源、引语；不删限定词与口径（「据官网」「2025 届」「观察口径」「可能」）；不把观察改成结论、把相关改成因果、把「有望改善」改成「改善了」。改完后每个**事实**都要能在原稿或素材（案例卡、访谈记录、核验清单）里指出出处，指不出来就撤销或进【需顾问确认】。
   允许加的只有两类，都要在【需顾问确认】里列出：① 素材里已确认、稿子却没用上的事实（核验清单里的数字和口径、案例卡里的动作和细节）；② IvyPath 自己对已确认事实的判断——「适合谁 / 不适合谁」「这一步为什么重要」「这份简历为什么更有说服力」。判断是我们声线的一部分，不是 AI 味；但判断不能悄悄长出新事实（「初级岗位受影响最直接」是判断，「某公司裁了 30% 分析师」是事实）。AI 味的稿子几乎都是空心的，套话删掉以后会露出洞，这两类是唯一合法的填充材料。
2. **数字带口径。** 届别、统计年份、base 还是总包、样本范围，一个都不能在改写中掉。口径混用是白皮书最常见的专业性翻车点。
3. **合规红线。** 不出现保录 / 100% 录取 / 包装背景 / 走捷径 / 内部资源保证 / 名校随便拿 / 低分也稳了；不暗示与校方特殊关系；不承诺结果、签证、实习、工作；「保录」「100% 就业」只允许出现在有官方来源引用的语境。改写时发现这类表述，删并列入【需顾问确认】。
4. **隐私与权属。** 学生化名、可识别组合信息模糊化，文书引用 ≤2 处且每处 ≤25 字；竞品文本一句不搬。
5. **宁可空缺不编造。** 【录入前由顾问替换】之类的结构化占位保留在原位。
6. **过度打磨是新的 AI 味。** 结构均匀比词汇黑名单更容易被识别。改完若每段等长、每句圆润、每段都有金句，就是把通稿改成了另一种通稿。
7. **AI 味是编辑信号，不是作者鉴定。** 本 skill 不输出「AI 含量」。
8. **消过毒的空壳不算交付。** 删完套话如果稿子已经撑不起它的体裁功能（白皮书一节没有可用的判断和数据、案例文的服务动作只剩一句、小红书正文不到 700 字），按第六节「填洞顺序」补到位；补不到位就明说缺什么，把它退回对应的生产线 skill，不能把一篇 300 字的备忘录当小红书交出去。

## 二、开工门检（一行输出，再动手）

```
【门检】体裁：白皮书 | 案例文 | 小红书 | 其他对外稿 ｜ 授权：最小改动（默认）| 深改（用户点名）｜ 受保护片段：学生原话 / 引语 / 数字与口径 / 课程代码 / 项目与公司名 / 表格 ｜ 素材来源：核验清单 / 案例卡 / 访谈 / 无
```

- **体裁**决定阈值档（第五节）。三档不能串：白皮书的表格是 GEO 资产，案例文的「不是X而是Y」是品牌句式，小红书的一个反问是平台肌理——放到另一个体裁里都是 AI 味。
- **授权**：「去 AI 味 / 改自然点 / 润色 / 审一下」= 最小改动；「重写 / 深改 / 按我们口吻重来」= 允许重排段落、重建句子，仍不新增事实。
- **受保护片段**默认逐字保留：学生和家长原话（可清口头语，不改判断与语气强度）、被讨论的措辞、课程代码、数字、表格单元格、引号里作为依据的引文。
- 有市场库时先读 `01_品牌中枢/去AI味写作规范.md` 与 `品牌禁用语.md`，与本 skill 冲突时以品牌中枢的最新条目为准。

## 三、通用规则（三个体裁都扫；每条有触发标记，命中才改）

改法遵守白名单纪律：只改命中的片段，改动限于解决该问题所需的最小范围，不顺便润色相邻文字。

| # | 症状 | 触发标记 | 改法 |
|---|---|---|---|
| 1 | **翻案腔 / 否定对举** | 「不是…而是…」「并非…而是…」「不在于…而在于…」「与其说…不如说」「表面…实际 / 看似…实则」「你以为…其实…」「问题不在于 X」；换任何字面做同一个动作都算 | 直接从正面下判断，先给判断再给依据。案例文的理念句例外，见五 |
| 2 | **三连排比与四字对仗** | 三个形容词/动词/身份整齐排列、末项拔高；「一、二、三」或「首先其次最后」通篇编号的小标题；「厚积薄发」式四字对仗小标题 | 合并能落成同一动作的项，身份评价另起一句；小标题改成内容短语。正文里的「首先…其次」不动（人类同样这么写） |
| 3 | **相邻句同骨架 / 段落一模板** | 连续两句以上逗号数、成分顺序、长度接近；每段都是「观点—解释—升华」；三个平级例子各占一段再接一句无信息的结论 | 打散其中一句的句法；按事实、原因、限制、行动等职责重排段落；平级例子合并主次，不删独立例子 |
| 4 | **破折号与冒号滥用** | 揭晓式破折号「答案很简单——专注」；「一句话总结：」「核心是：」「原因如下：」提示语冒号；一行只为宣布下面有列表而存在的空转句「几种典型场景：」 | 破折号改逗号句号；提示语不承担信息就删，承接上文就只换标点；空转句改成有内容的判断。句中总说加分说的冒号、引出原话的冒号不动 |
| 5 | **bullet 与编号代替论述** | 叙事、观点、短答被拆成编号或 bullet 只为显得完整；大段要点罗列 | 恢复自然段。操作步骤、参数对照、白皮书数据表保留 |
| 6 | **拟人化理想喻体** | 「像一位智慧的导师」「贴身的数字秘书」「永不疲倦的初级审查员」，喻体带褒义修饰或后接「不仅…更…」 | 换成这东西实际做了什么。具体的人当喻体（「像一个老师傅」）不动 |
| 7 | **概括盖住具体 / 名词化** | 同段已有具体数值或对象，却用「显著提升」「大幅增长」「大量」「众多」概括；「完成了对…的…」「实现了…的提升」「进行了…的优化」 | 把已有的具体值提到概括词位置；恢复动词。原文没有数据时只恢复动词，不许造数 |
| 8 | **起手式与元叙述** | 「说白了」「说穿了」「先说结论」「本质上」「归根结底」「换句话说」「值得注意的是」「不难发现」「重点来了」「答案很意外」「你只需要」「我有一个很直接的感受」「更值得注意的是」「这里要提醒一点」——只宣布下一句重要、自己不承担信息的句子 | 删掉，把事实或判断放到它的位置。小红书、案例文全文这类过渡最多留一处；白皮书允许「先说结论」「提醒一句」这一档，限额见五 |
| 9 | **五种翻译腔** | 中心名词前修饰超过十五字或连续两个「的」；「当…时，」前置从句；「对于…来说 / 关于… / 在…方面」前置话题壳；段首「然而 / 因此 / 此外 / 与此同时」当路标；「这意味着 / 这表明 / 这说明」复述上一句 | 拆成两个分句；删「当」「时」；对象直接放主语位；连接词移到主语后或换「不过 / 其实 / 也」；并入前句。**只处理这五种**，被动句、名词化、长句本身不是翻译腔 |
| 10 | **段首零主语评论** | 非首段以「听起来 / 看起来 / 值得注意的是 / 更重要的是 / 关键在于 / 不难看出」开头，且整句没有「这 / 那 / 其 / 此」回指上文 | 补一个「这」字或点明评论对象。首段不算 |
| 11 | **AI 高频词与空心词** | 赋能、抓手、闭环、打造、全方位、深耕、助力、保驾护航、至关重要、淋漓尽致、颠覆、重磅、干货满满、浓墨重彩、大放异彩、脱颖而出（≤1）、抛出橄榄枝（≤1，标题正文合计）、圆梦名校、厚积薄发、未来可期、拭目以待、综上所述、总而言之、一言以蔽之、毋庸置疑、众所周知、由此可见、「随着…的发展」「在当今…的时代」开头、真正、其实、值得一提的是、某种程度上、不得不说、天花板（每篇 ≤1）、两开花之类网络梗 | 空心词直接删；高频词换成具体动作或事实；换不出具体内容就删整句 |
| 12 | **空洞结尾与正能量缝合** | 「未来可期」「让我们拭目以待」「祝愿…」；负面处境后突然接与事实无关的励志结论；总分总八股（开头预告 A、B、C，结尾「综上所述 A、B、C 表明」）；每段结尾一句金句 | 停在最后一个有信息的事实、判断或具体下一步；负面事实后原文确有态度变化或行动结果才保留转折 |
| 13 | **自夸形容词与空泛点评** | 专业、用心、负责、高效、贴心、优秀、值得、极好；「就业极好」「服务很到位」 | 换成素材里已有的动作、数字、时间、场景（「2025 届 98.5% 六个月内接 offer」「改了六稿，其中第三稿把主线从『兴趣』换成『证据』」）；素材里没有就删，不造 |
| 14 | **假共识与模糊归因** | 「业内人士认为」「研究表明」「很多人说」「大家都知道」，没有来源；「任何人 / 各种场景」范围超过原文 | 具体到来源；具体不了就保留归属并在稿外标缺来源，或收窄范围。不能只去掉「研究表明」让无源论断变成裸事实 |
| 15 | **鸡汤金句与假揭示** | 「看似 X，本质 Y」「真正拉开差距的是」「底层逻辑」；对仗工整、脱离本段仍成立的判断句 | 让事实先建立关系，再直接写归因；合格的结论句必须回指刚讲的事 |

## 四、不作为改写理由（和第三节同等效力）

以下特征看着像 AI 味，实测站不住，或者删了更像机器。命中也不改。

| 特征 | 为什么不改 |
|---|---|
| 句长、段落长度不够参差 | 实测与人类写作无差别；不要为了造节奏拆段、调句长 |
| 单字虚词偏少（就 / 很 / 了） | 补虚词无法验收，容易把正式稿改成口语 |
| 反复写同一名词、少用代词 | 人类比 AI 更常重复同一名词；同义轮换才是机器指纹 |
| 被动句、名词化、长句本身 | 现代汉语书面语的正常写法 |
| 正文里的「首先…其次…最后」「第一，」「一方面」 | 与人类写作无差别；只管小标题通篇编号 |
| 句内同构排比（「提升效率，降低成本，优化体验」） | 人类用得不比 AI 少；只处理句间重复 |
| 问句、设问、问句小标题、FAQ | 正文问句人类远多于 AI；白皮书 FAQ 天然是问句 |
| 比喻本身、比喻独立成段、具体的人当喻体 | 只处理理想化职业人格喻体（三-6） |
| 冒号引出原话、解释、白皮书表格；书名号 | 规范用法 |
| 有信息的列表与表格 | 白皮书的表格是 GEO 资产，案例文的档案卡是信任资产 |
| 学术 / 公文 / 技术语体里的术语名词化 | 稳定术语不拆（「兼容性」「初始化」） |
| 顾问和作者的判断，即使抽象 | 「系统化实践」是原文判断，不能因为抽象就删；缺依据可以在稿外指出，不能替作者撤回 |
| 学生和家长原话里的口语、犹豫、自嘲 | 内容，不是空话 |
| 案例文里加粗的理念句、小红书里的一个反问 | 在体裁限额内就是肌理（第五节） |

对某处是否命中规则没有把握时，保持原文。

## 五、体裁模块（阈值与专项）

### 白皮书（官网专业方向入口，网页正文承担 SEO/GEO）

- **语体**：信息型正式，判断先行。允许的口语连接词只有一档：「先说结论」「一个实用的判断」「提醒一句」，全篇 ≤3 处；不用网络梗，「天花板」≤1。判断句的力度用「慎入」「不建议申请」「要先想清楚」这一档，不用「那就不要来了」这类口头话；「那么…适合谁呢？答案很简单」式的自问自答改成直接陈述。
- **无来源的趋势句按假共识处理**：「越来越多的中国学生开始关注」「行业热度持续上升」「最炙手可热的方向之一」这类没有数据的趋势判断，删掉或改成有出处的说法（IvyPath 自己的咨询量、官方申请数据）；留着它们等于留了一个「研究表明」。
- **结构**：8 节固定目录（关键结论 / 专业概览 / 行业岗位与公司 / 核心申请要求 / 精选项目清单 / IvyPath 录取观察 / 申请时间线 / FAQ / 数据来源）不动；小标题用内容短语；表格与问答鼓励；结论先行、每个数据带截至日期与口径；FAQ 问句保留。
- **阈值**：「不是X而是Y」≤1；对仗排比 ≤1（三项全是空泛能力词的排比——「更强的适应能力、更深的技术功底、更广的业务视野」——不算排比，按三-13 空泛点评处理：落到具体能力或删）；破折号少用；每节至少一处不完美信息（风险、短板、坑）；结尾收在具体下一步或具体判断。
- **节的功能不能洗没**：01 关键结论删完套话后必须仍然是 3–5 条带数据或案例托底的判断，03 雇主分层每层要有一个具体锚点。洗完只剩「每一层都招数据人才」这种句子，就用核验清单里的事实补，补不了就在【需顾问确认】里退回 major-whitepaper-writer 补料。
- **专项**：数字与口径逐个核对不掉；无法核验的精确数字（录取率、班型）只能是「观察口径」或定性表述；排名表述（「第一档」「天花板」）是编辑判断，读者挑战时以入选口径回应。绝对化承诺只在有官方来源引用的语境。
- **不改**：岗位光谱表、雇主分层、薪酬三口径的表格结构；「适合谁 / 不适合谁」的判断句。

### 案例文（公众号学员案例，默认 D 体·IvyPath 主笔叙事体）

- **口吻**：文气、克制、知识分子腔，每句在解释而非炫技；情感只在结尾释放一次。学生是「被看见的人」，不是战利品。
- **句式限额**：「不是X而是Y」放宽到 ≤3，但只许用在加粗的理念句，不许用在过渡和小结；理念句加粗每板块 ≤1；解释段每段 ≤3 句；场景白描动词优先、形容词少。
- **结构**：档案卡 → 场景开场（收在「他第一次意识到：…」）→ 信任起点 → 背景补强（动作 + 为什么）→ 关键抉择 → 选校逻辑三层 → 文书打磨 → 结果与收束 → 声明 + 低调 CTA。结果 / 放榜段的小标题必须带具体词（offer / 录取 / 校名），抽象意象只许在开头场景和结尾金句出现。
- **专项**：每个「我们做了什么」有数字 / 时间 / 场景之一，否则删；自夸形容词计数 = 0；服务动作 ≥3、关系细节 ≥1、项目冷知识 ≥1（缺了回素材找或问用户，不造）；反差在标题和前三段出现；「IvyPath 小贴士」插播 ≥1；建议板块 3 条可操作；文末真实案例 + 隐私声明。
- **案例文高危 AI 腔**（专项排查）：浓墨重彩的一笔、大放异彩、脱颖而出 ≤1、抛出橄榄枝 ≤1、圆梦名校、厚积薄发式四字对仗小标题、每段结尾的升华句。
- **不改**：D 体用词 DNA 句式（「我们没有急着让他…，而是…」「但他的情况不一样」「他第一次意识到：」）是我们的口吻，不按翻案腔处理；学生与家长原话式疑问的问句排列。

### 小红书（手机上滑动阅读，一条主线）

- **小红书的「最小改动」是围绕一个张力重建，不是逐句修补。** 内容工厂腔的稿子每段一个揭晓，把揭晓删掉就只剩骨头；一篇八百字的帖子重写成本很低，守恒的单位是事实、数字、案例和作者的判断，不是句子。做法：先列出稿子里所有事实和判断，选一个张力当主线，把事实按「张力 → 证据 → 对读者意味着什么 → 边界 → 可用的判断」重新讲一遍，长度回到 700–1200 字。用户点名「只改几句」时才逐句修。
- **一条主线**：发现型 / 案例型 / 经历型 / 建议型四选一；开头三行内到达张力（一个数字、一个反差、一个场景），不以「最近很多人问」开场除非真发生过。
- **篇幅与节奏**：700–1200 字；段落 1–4 句且长短不一；允许偶尔一句独立成段；不是每段都落在 punchline。
- **限额**：一个钩子，不是八个；口号式句子 ≤2；插入的口语词 ≤2 且不按词表配额硬塞；反问 ≤1；不强凑三条；不用「建议收藏」「少走十年弯路」一类互动钓饵；emoji、加粗、hashtag 可选，hashtag ≤3 且只在有助于发现时用。
- **准确性不做附录**：caveat 贴着它限制的那句话写，压成一两句，不写「研究边界」章节；把观点标成看法或删掉，不升级为事实；保留有证据支持的方向性结论。
- **两个极端都不要**：内容工厂（每段一个揭晓、「真正可怕的是」、堆比喻和黑话模拟个性）和研究备忘录（「先讲数据直接显示的」、逐条标注推测、每个 caveat 单独成段、拒绝下判断）。
- **实操类内容**：命令、代码、prompt 模板、配置给可直接复制的版本，用场景叙述带出操作，不写「第一步第二步」手册体。
- **交付**：三个标题（发现型 / 读者决策型 / 案例或反差型）+ 正文 + ≤3 个 hashtag（可无）；审计和方法论不进发布稿。

### 其他中文对外稿（推文、项目解读、FAQ、活动文案）

默认按白皮书档执行；明显是平台化短稿时按小红书档；有学生故事时按案例文档。拿不准时在门检里说明选了哪一档。

项目解读借用白皮书档的克制语气与语言检查，**不套用白皮书固定目录**。文章结构、官网内嵌或独立文章模式、事实分工和必要解释由对应生产 skill 或用户要求决定；语言终审不擅自增加标题钩子、关键数字卡、适合人群段或总结。

## 六、工作流

### 模式选择

| 用户说 | 模式 | 交付 |
|---|---|---|
| 「审一下」「只标问题，不改写」「像不像 AI」 | **审阅**（只标问题） | 问题清单 + 判断；只引用有问题的片段，不交替换全文，不输出评分 |
| 「去 AI 味」「改自然点」「润色」或不说 | **最小改动**（默认） | 修订全文 + 清单 + 复扫 |
| 「直接改文件」「原位改」 | **原位编辑** | 只改命中片段，报告改了哪几处 |
| 「重写」「深改」「按我们口吻重来」 | **深改** | 允许重排段落、合并拆分、重建信息架构；仍不新增事实、不删限定词 |

### 最小改动流程

1. **通读全文 + 素材**。白皮书、案例文这类长稿先列信息账本（人物、事实、数字与口径、时间、专名、来源、限定词、学生原话）；小红书一篇 800 字在心里过一遍即可，不用把流程写给读者看。
2. **判体裁、定阈值**（第五节），门检一行。
3. **按第三节逐条扫**，输出问题清单（位置｜规则编号｜原句｜改法）。第四节的项命中也不改。
   同时做读者理解检查：未解释的术语、跳过的理由、缺少适用条件的建议，能从现有素材补清就补清，缺依据则标出缺口；不靠缩短句子掩盖解释不足。对反复出现的事实，区分必要的查阅信息与没有增量的复述，按生产稿的信息分工处理。保留明确届别、日期与统计范围，不用「最新」「毕业年薪」替换原有精确信息；不为强调把每个半句拆成独立段。
4. **判断修补还是退回**：词汇命中 ≥5 处且跨 ≥3 类，同时段落均匀、每段同构、结尾统一升华——修补没用，建议回到生产线 skill 按素材重写该节，并说明理由。手头没有生产线素材（核验清单 / 案例卡）可回时，视同深改授权，按稿内已有事实和用户给的素材说明重建，并在门检里注明。
5. **改**：只动命中片段；受保护片段逐字保留；压篇幅时先删整段最弱的信息，再删功能段，最后才在句内删完整意群，不逐词抠。
5b. **填洞**（删完套话后稿子撑不起体裁功能时执行，顺序不能颠倒）：
   1. 把素材里已确认、稿子没用上的事实补进去：核验清单里的数字和口径、案例卡里的动作 / 时间 / 场景、小红书素材说明里的细节；每补一处在【需顾问确认】记出处
   2. 给事实补 IvyPath 的判断句：这个数字对申请者意味着什么、这一步为什么重要、这个例子说明了什么（铁律 1 ②）
   3. 仍然撑不起来：在【需顾问确认】写清缺什么（一个雇主锚点 / 一个带数字的服务动作 / 第二个发现），退回对应生产线 skill 补料，不交空壳
   填洞的禁区和铁律 1 一样：不造数据、不造案例、不造来源；不用形容词凑字。
6. **复扫**（在修订稿上再做一遍）：
   - 列段落字数与首尾句，看均匀度有没有反而变好（变好 = 过度打磨）；每段是否都以金句收尾
   - 账本核对：每个实词回指得到出处；限定词与口径一个没少；学生原话都活着；合规红线为零
   - 同页交叉核对：正文里用文字复述的数字要对得上同一页的表格和数据行（「私立同行三分之一的价钱」对表里的 $45,090 / $97,200 是 46%，应写「一半左右」）；对不上的按事实错误改，不当 AI 味处理
   - 体裁限额计数：不是X而是Y / 对仗 / 破折号 / 口语连接词 / 反问 各几处
   - 大声读一遍：像 IvyPath 的人在跟一个具体读者说话吗
   - 体裁功能对照（铁律 8）：白皮书一节还有判断和数据吗、案例文的服务动作还有数字/时间/场景吗、小红书够 700 字吗；没到就回 5b，不能直接交
7. **交付**。发布稿正文里不留任何审计痕迹、编辑标签或方法说明。

### 输出契约

长稿（白皮书一节、整篇案例文）按此输出；小红书与短稿用紧凑版（问题清单 + 修订稿 + 一句复扫）。白皮书多节时按节交付，末尾附全篇复扫。

```
【门检】体裁 ｜ 授权 ｜ 受保护片段 ｜ 素材来源

【问题清单】
| # | 位置 | 规则 | 原句 | 改法 |

【修订稿】
（全文；原位编辑模式只给改动段）

【改动摘要】
· 3–8 条

【复扫】
· 段落结构与均匀度判断
· 守恒核对：实词出处 ✓ / 限定词与口径 ✓ / 原话 ✓ / 合规 ✓
· 限额计数

【需顾问确认】（只在有事实、合规或素材缺口时出现）
· 缺来源的论断 / 掉口径的数字 / 合规红线表述 / 回指不到出处的细节 / 素材里找不到的服务动作
```

## 七、与其他 skill 的衔接与学习闭环

- **write-graduate-program-analysis**：负责项目事实、读者解释、整页去重及官网内嵌/独立文章结构；本 skill 只做通用语言终审与信息保真复查，按生产稿既定结构执行。项目改稿实例回填该生产线的 `references/SHARED-lessons.md`，不在两边复制同一套项目写作规则。
- **major-whitepaper-writer**：第 6 步三关审稿中的「AI 味关」= 调用本 skill（白皮书档）；数据关、合规关仍归它，本 skill 只把发现的数字口径问题和合规表述列进【需顾问确认】。
- **case-story-writer**：Step 5 质检的去 AI 味自评 = 调用本 skill（案例文档）；合规清单、独创性清单、配图生产单仍归它。
- **write-xiaohongshu-posts**：它的改写流程与 AI 词组扫描已并入本 skill 小红书档；出稿后的 corrective pass 调用本 skill。
- **学习闭环**：顾问对本 skill 产出的每处修改，提炼成规则回填到对应生产线的学习文件——项目分析与采用 SHARED 的白皮书优先用 `references/SHARED-lessons.md`（旧版才用 `references/lessons.md`）、案例文 `references/quality-check.md` 用词 DNA 区、市场库 `01_品牌中枢/去AI味写作规范.md` 第九节；不在本 skill 里另建规则库。记录采用与未采用项，人工终稿不自动成为事实依据；共享文件按生产线的同步约定增量合并，攒够三条同类，再改本 skill 的阈值。

## 八、示例（改法的分寸）

**白皮书句：概括盖数据 + 起手式**

> 改前：值得注意的是，该项目实现了就业率的显著提升，2025 届毕业生在六个月内的就业情况非常理想，充分体现了项目在行业中的强大竞争力。
>
> 改后：2025 届毕业生 98.5% 在毕业六个月内接到 offer（官方就业报告，2026-01 更新）。

动了什么：删起手式；把已有的具体值提到概括词位置；删无事实支撑的评价。数字和口径来自核验清单，没有核验清单时改后版本不能写，只能删「显著提升」并进【需顾问确认】。

**案例文段：自夸形容词换动作**

> 改前：我们的顾问团队非常专业、用心，全方位地为他打造了一套个性化的申请方案，帮助他在激烈的竞争中脱颖而出，最终圆梦名校。
>
> 改后：我们没有急着让他补一段科研，而是先把他大二那门数据库课的期末项目重新拆开，看哪些部分能撑起「用数据解决业务问题」这条主线。这一步做完，选校名单才定下来。

改后的动作、课程、主线判断全部来自案例卡；案例卡里没有这些细节时，只能把自夸句删掉并列入【需顾问确认】请顾问补。

**小红书段：内容工厂腔**

> 改前：说白了，很多人申请金融硕士最大的误区不是背景不够，而是根本没搞懂项目在筛什么。重点来了：真正拉开差距的，是你能不能证明自己会用数据说话。看懂这一点就够了。
>
> 改后：72 份录取简历里，写了 Python 项目的有 37 人，但只有 19 人写了数据规模、模型比较或结果。金融硕士项目在筛的是后一种人。

动了什么：删起手式、翻案腔、假揭示和「看懂这一点就够了」，把原稿后文已有的数字提到开头当张力。数字必须是原稿或素材里已有的。

## 九、反模式（本 skill 绝不做）

1. 为了「更像人」加错别字、emoji、网语、第一人称感受、个人经历、幽默——自然不等于口语化，加进去的都是编造
2. 按词表配额硬塞口语词；全文一刀切禁冒号、禁列表、禁被动句
3. 逐词压字数；为了造节奏拆段落
4. 把学生原话修成标准书面语；把顾问的判断当空话删掉
5. 用同义词替换黑名单词（「赋能」→「助力」）——换词不换写法还是机器味；改法是落到具体动作
6. 输出「AI 含量」或「这篇是 AI 写的」判定
7. 擅自补数据、补来源、补案例细节；擅自把观察写成结论
