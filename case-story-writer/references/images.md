# 配图工作流(公众号案例文)

成稿的每个 `[配图:____]` 位,同时输出一张**配图生产单**(见文末格式),让配图和文字一次交付。
配色遵循品牌库 `01_品牌中枢/品牌配色方案_RLG×IvyPath.md`:公众号案例文以墨青 `#1D4752` + 米白 `#F7F5EE` + 金黄点缀 `#FFD24D` 为主,猩红只作小面积强调。

## 红线(先读)

1. **前东家的物料一张都不用**:带他们logo的offer海报、水印聊天截图、设计图,不复用、不P掉logo再用。P图等于篡改别人的物料,被认出来是公关事故。
2. **offer原件属于学生**:大学发的录取信/邮件/portal页面,学生本人有权提供和授权展示。走"找学生要原件"这条路,永远比处理前东家的图干净。
3. **对话卡只重现真实发生的沟通**:内容必须来自真实记录或双方确认的回忆,底部固定标注"内容整理自当时沟通记录"。不伪造微信截图样式,不编造对话。

## 五类配图位与来源

### 1. 场景意象图(开头场景段/交换段)
- 来源:无版权图库(Unsplash/Pexels)或网络图。网络图必须标注 `*配图源自网络`(母本做法)。
- 成稿时为每个意象图位自动给出 **3个英文搜索词**(如山寺场景:`japanese mountain temple` / `cedar forest shrine steps` / `osaka temple mist`)。
- 学生真实照片优先于图库,标注 `学员供图,禁止转载`。

### 2. offer卡(结果段,2~3张)
SOP:
1. 向学生要原件:录取邮件截图 / 申请portal的decision页 / offer PDF首页(学生自己截,不经前东家)。
2. 脱敏:姓名、学号、地址、申请ID打码;保留校名、项目名、日期。
3. 套模板 `配图模板/offer卡模板.html`:替换截图和校名文字,浏览器打开截图导出。
4. caption 固定:`学员授权展示`。
- 学生联系不上/不愿提供 → 该图位改用文字化结果卡(校名+项目列表的设计卡),不硬凑截图。

### 3. 对话卡(服务证据位)
两条路径,按素材情况选:
- **A 自己微信里有原始记录**:直接截图 → 裁掉一切前东家痕迹(群名、工作号昵称、头像) → 打 IvyPath 水印。裁剪脱敏可以,内容不改一个字。
- **B 记录不在了/在前东家工作号**:用 `配图模板/对话卡模板.html` 把真实对话内容做成品牌样式的设计卡。它长得就不像微信截图(墨青/米白气泡+衬线标题),底部自带"内容整理自当时沟通记录"标注——这是引用设计,不是伪造证据。
- 对话卡内容优先挑:拒绝偷懒的瞬间、深夜时间戳、学生的情绪原话(service-trust.md 手法2/4/5)。

### 4. 表格·流程图(选校三层/时间线/规划表)
- 用 `配图模板/` 里的卡片模板改,或按 `01_品牌中枢/配图设计规范SOP.md` 的样式出;数据必须来自本案真实素材。

### 5. 学生供图(校园/活动/交换)
- 找学生要,标注 `学员供图,禁止转载`;涉及他人面部做模糊处理。

## 配图生产单(成稿附带,每图一行)

```
| 图位 | 类型 | 来源/动作 | 搜索词或模板 | 脱敏项 | caption |
|---|---|---|---|---|---|
| 开头场景 | 意象图 | Unsplash搜索 | japanese temple / ... | - | *配图源自网络 |
| 放榜段 | offer卡 | 向学生要邮件截图 | offer卡模板.html | 姓名/ID | 学员授权展示 |
| 文书段 | 对话卡 | 路径B设计重现 | 对话卡模板.html | 昵称 | 内容整理自当时沟通记录 |
```

生产单跟成稿一起存,配图做完在行尾打勾。
