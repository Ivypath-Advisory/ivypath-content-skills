# IvyPath 案例模仿训练（市场实习生）

四步走：**选案 → 初改稿训练包 → 批改回稿 → 素材包**。目标是让市场实习生按「读好案例 → 看我们怎么改 → 自己改 → 被批改」的顺序，学会写我们官网的案例文，同时学会做 offer 图、知道该向后端要哪些服务素材。

和用户、实习生沟通一律用中文。

## 二、铁律（四步都适用）

1. **授权分级决定能不能上线**（目录里的「授权状态」列）
   - **A 授权清单**：PH 授权清单内的文章，可以进上线流程。第一次用前先跟 Daniel 确认授权范围（文字、图片分别能否用）。
   - **B 本团队经手**：清柚数据表里的学员，是我们团队当年服务的学生，可以写成我们的案例。但清柚原文和图片一张不用（前东家物料）：事实以数据表、后端记录和学生提供的原件为准，上线前必须确认学生授权。
   - **C 仅培训**：其余全部（PH 非授权文、常青藤、拓达、清柚非本团队学员）。只做训练用：训练稿每页页眉写「培训样稿｜改编自外部公开案例｜不得发布」；不进官网、公众号、小红书等任何对外渠道；不能说成 IvyPath 学员。
2. **竞品句子一律不搬**：要上线的稿和原文跑 12 字滑窗查重，命中只能是校名、项目名、数字这类专有名词。
3. **事实不加不改**：GPA、标化、录取学校与项目、奖学金、时间以原文或资料卡为准。没有的写【待补】，不编。
4. **隐私**：学员称「姓的英文首字母 + 同学」；不出现真名、学号、邮箱、电话、可识别的人脸；offer 图必须打码。
5. **合规**：禁用「保证、包过、保录、100%录取、最强、第一（第一类/第一次等序数除外）、包装背景、走捷径、内部资源」；改写稿里不出现竞品机构名和竞品老师名（A/B 级改成「我们」和角色名，C 级改成「机构」）；A/B 级上线稿页脚保留「本文源自 IvyPath 学员真实申请案例。未经许可，请勿转载。」

## 三、第一步：选模仿案例

**输入**（任意组合）：本科学校、本科专业、目标或已录取的项目（或白皮书方向 WP01–WP08）、用途（培训 / 上线）、要几篇。

**做法**
1. 用 Python 读目录 CSV（`encoding="utf-8-sig"`）。学校名统一中英文和简称：罗格斯=Rutgers=RU，石溪=Stony Brook=SBU，雪城=Syracuse，康大=UConn，纽大=NYU，上纽=NYU Shanghai，UCSD=加州大学圣地亚哥分校，以此类推。
2. **按匹配层级筛**（先高后低，够数就停）：
   - L1 同本科 + 同录取项目（或同一个白皮书 05 节项目）
   - L2 同本科 + 同白皮书方向
   - L3 同类院校 + 同项目或同方向：UC 系互补；罗格斯 / UConn / 石溪互补；布兰迪斯 / 雪城互补；NYU / NYU Shanghai 互补
   - L4 任意本科 + 同项目
3. **打分排序**：最终去向在本方向 +3；录了白皮书 05 节项目 +2；2025 季及以后 +2，2023–2024 季 +1；PH 正文 ≥3,000 字 +1；有 GPA +1；本方向录取每个 +0.5（最多 +1.5）。
4. **按来源判断能学什么**：
   - 学写法优先选 PH（学员第一人称访谈，人味最足）；
   - 清柚只列录取，适合看同背景能录哪些项目，不适合模仿写法；
   - 常青藤、2025 下半年以后的拓达 AI 腔重，只拿来当反面示例。
   - 用途为「上线」时只出 A/B 级。
5. **输出选案卡**（3–5 条）：编号｜来源｜授权｜本科 / 专业 / GPA / 标化｜命中的录取｜最终去向｜匹配层级与理由｜正文字数｜链接。用户在场就请他挑；没人回复就取第一名继续，并在交付时写明。

## 四、第二步：初改稿训练包（Word）

先在 Chrome 里读完原文全文，再用 docx skill 生成 `训练包_<本科简称>_<方向>_<案例编号>_<日期>.docx`，包含五部分：

1. **案例卡**：来源、授权等级、链接、学员背景、全部录取、最终去向，只写事实。
2. **原文拆解表**：原文逐段写出它的职责（导语 / 资料卡 / 动机 / 难点 / 选校 / 背景提升 / 文书 / 推荐信 / 面试 / 结果 / 寄语 / 广告），对应到我们长页的栏目（封面、录取结果、01 起点、02 问题诊断、03 从兴趣到证据、04 关键经历、05 三层选校、06 文书打磨、07 结果时间线、结尾），并标「保留 / 改写 / 删除」和原因。
3. **初改稿**（按我们的上线要求）
   - **结构**：按长页顺序写。官网标题用 SEO 格式，例：「GPA3.45无GRE录取哥大东亚文化研究：D同学五校录取案例」；另写一个两行 H1 和一句副题。
   - **口吻**：照口吻母本，面向读者用「你」，机构自称「我们」；克制、具体、不煽情、不用 emoji；数字带上下文；每段先写事实再给判断。学员原话里的口语和英文夹杂（其实、感觉、offer、mock、AO）照留，这些不算 AI 味。
   - **信息下限**：至少有一个没录上或主动放弃的项目和原因、一个犹豫过的决定、具名角色（文书导师 / 班主任 / 【顾问】）加上他们的具体动作、至少一个数字，以及两处「我们做了什么」。
   - **量化上限**（每万字）：「不是…而是」≤0.5，「真正」≤1，破折号 ≤0.5。以下为 0：金句收尾，以及赋能、打造、全方位、深耕、助力、保驾护航、至关重要、闭环。
   - **替换**：竞品机构名和老师名按授权等级替换；C 级保留原学员化名，同时加页眉水印。
   - **批注**：在 Word 批注里写「为什么这么改」，8–12 条，结构、事实、口吻、去 AI 味、合规、隐私各至少 1 条。
4. **练习任务**：给实习生 3–5 个可以检查的任务，例如：
   - 把「02 问题诊断」改成自己的话（150–250 字），三个事实点不能丢；
   - 找出初改稿里你觉得还像 AI 写的 2 句，改掉并说明理由；
   - 给每个录取写海报名条（校名中英 + 排名口径 + 项目名）；
   - 列出写这篇需要向后端要的 5 样素材，并写明在系统哪里找；
   - 写 SEO 标题和 meta description（不超过 80 字）。
5. **交回前自检清单**：事实对照、禁用词、隐私、量化上限、栏目齐全、任务完成，逐项打勾。

交付前先对初改稿跑「七、检查脚本」，然后用 SendUserFile 交付。

## 五、第三步：批改实习生回稿

**输入**：实习生交回的 Word，可能带修订和批注。

1. 取出接受修订后的全文，以及各练习任务的答案。
2. 按栏目和初改稿做对比，列出改了哪里。
3. 跑检查脚本，检查这几项：
   - 事实一致：数字、校名、项目和资料卡对照；
   - 禁用词、隐私、量化上限；
   - 和原竞品文做 12 字查重，列出全部 12 字以上的重合；
   - 栏目是否齐全，信息下限是否达到。
4. 按 `ivypath-humanize-zh` 的规则做语感审：只指出问题、给示范改法，不整篇替实习生重写。
5. **打分（100 分）**：事实准确 20，结构与信息 20，口吻与去 AI 味 20，合规与隐私 15，原创度（查重）15，练习任务 10。每项写扣分理由，并给一处示范改法。
6. **批改报告**（Word）：总分；三处改得好的地方；三处最该改的地方（原句 → 建议）；下一篇建议重点练什么。
7. **出终稿的条件**：用途为「上线」且授权为 A/B 级时，再出一份推荐终稿，过一遍 humanize-zh 终审。C 级永远不出可发布稿。
8. **训练记录**：用户要求时，在 Dropbox 训练记录表里追加一行（实习生、案例编号、日期、分数、主要问题）。写入前先告诉用户路径，得到确认再写。

## 六、第四步：素材包（offer 图 + 服务内容 + 向后端要素材）

### A. 原案例的 offer 图（学习用）
- 在 Chrome 里打开原文，定位图片：资料卡之后、「offer / 录取 / 捷报」附近的图，多半是录取截图或捷报海报。每张记下：
  - 第几张图；
  - 类型：offer letter 截图 / 机构捷报海报 / 邮件截图 / 学校系统截图；
  - 显示了什么：校名、项目、奖学金、日期；
  - 打码了哪些地方。
- 默认只给链接和位置说明。用户要截图时才截，放进训练包附录，标「外部物料·仅供内部学习」。B 级（清柚）的原文图片不截、不存。

### B. 我们的 offer 图怎么做（教学要点）
- **版式**：按 README 第 2 节的「2026 OFFER捷报」海报规格。从上到下：
  - 校园照 hero，加深青蒙版，底部斜切；
  - 白框标题「年份 / OFFER捷报」；
  - 湖绿名条：校名 +「全美大学排名 TOPxx」；
  - 校徽；
  - 「入读」标记和奖学金行，确有其事才放；
  - offer letter 顶部裁切，露出信头和 Congratulations 段；
  - 页脚「一唯教育 · IvyPath Advisory ／ ONE PATH · ONE VISION」，正中放半透明水印 logo。
  - 海报内字体用 MiSans。
- **打码**：遮掉姓名、称呼行、地址、学号或申请号、邮箱、电话、签名、二维码、照片；保留信头、校名、项目名、祝贺段、奖学金金额。微信服务截图同样打码（头像、昵称、手机号）。
- **排名口径**：USNWR 全美综排，写明年份，上线前由市场确认。校名太长用通用缩写（如 WashU）。
- **示范**：给本案例每个 offer 填一张「海报信息表」，列校名中英、排名、项目、入读和奖学金、letter 裁切位置，再附一张空白表给实习生用于我们的学员。

### C. 服务内容，以及向后端要什么
- **服务动作表**：把原文里的服务动作抽出来，列「阶段｜原文做了什么｜对应我们长页哪一栏｜我们自己的案例需要什么证据」。阶段包括规划、选校、背景提升、文书、推荐信、网申、面试、选 offer、奖学金。
- **素材在我们系统的哪里**（问后端时直接说位置）：

| 要的素材 | 系统里的位置 | 找谁 |
|---|---|---|
| 选校过程、候选与定校、梯队 | 定校书（候选 → 定校两段式） | 申请顾问 / 后端顾问 |
| 文书老师、改了几稿、主线怎么变 | 文书分配表、文书老师端 | 文书老师 |
| 推荐信组合 | 推荐人库 | 后端顾问 |
| 面试辅导（面试类型、mock 次数） | 申请管理 · 面试 | 后端顾问 |
| Offer 原件、奖学金、入读决定 | 申请管理 · Offer 材料 | 后端顾问 |
| 背景提升、实习、科研 | 学业规划、实习建议 | 规划顾问 |
| 学生原话 | 文书素材问卷、学生问卷 | 后端顾问转学生 |
| 服务过程截图（需打码） | 学生服务微信群 | 班主任 / 后端顾问 |
| 公开授权 | 合同授权条款 + 学生确认 | 销售 / 后端顾问 |

- **消息草稿**：再写一段能直接发给后端的消息，写明学员化名、要哪几样、文件格式、打码要求和截止时间。

## 七、检查脚本

每次交付前、批改时都跑一遍。`src` 是原竞品文，`draft` 是要检查的稿件：

```python
import re

AI = {"不是…而是": r"(?:不是|并非|并不是|不在于?)[^。！？\n]{1,30}(?:而是|更是|而在于?)",
      "真正": r"真正", "破折号": r"——|—"}
CAP = {"不是…而是": 0.5, "真正": 1.0, "破折号": 0.5}
BANNED = (r"保证|包过|保录|100%录取|最强|第一(?!类|次|轮|段|步|稿|封|个|位|批|学期|年)|包装背景|走捷径|内部资源"
          r"|赋能|打造|全方位|深耕|助力|保驾护航|至关重要|闭环")
PRIVACY = r"[\w.+-]+@[\w-]+\.[\w.]+|\b1[3-9]\d{9}\b|\b\d{8,}\b"


def rates(t):
    n = max(1, len(t))
    return {k: round(len(re.findall(v, t)) * 10000 / n, 2) for k, v in AI.items()}


def over_cap(t):
    r = rates(t)
    return {k: v for k, v in r.items() if v > CAP[k]}


def banned(t):
    return sorted(set(re.findall(BANNED, t)))


def privacy(t):
    return re.findall(PRIVACY, t)


def overlap(src, draft, n=12):
    norm = lambda s: re.sub(r"\s+", "", s)
    a, b = norm(src), norm(draft)
    grams = {a[i:i + n] for i in range(len(a) - n + 1)}
    hits, i = [], 0
    while i <= len(b) - n:
        if b[i:i + n] in grams:
            j = i + n
            while j < len(b) and b[i:j + 1] in a:
                j += 1
            hits.append(b[i:j]); i = j
        else:
            i += 1
    return hits  # 只允许校名 / 项目名 / 数字类专有名词
```

## 八、交付与命名

- **格式**：训练包和批改报告都用 Word，用 SendUserFile 交付。要放进 Dropbox 时，先说清路径，得到用户同意再写。
- **命名**：
  - `训练包_<本科简称>_<方向>_<案例编号>_<日期>.docx`
  - `批改_<实习生>_<案例编号>_<日期>.docx`
  - `素材清单_<学员化名>_<日期>.md`
- **给用户的回复**只写四件事：选了哪篇和为什么、交付了什么、实习生下一步的任务、还缺哪些素材。不复述文件内容。
