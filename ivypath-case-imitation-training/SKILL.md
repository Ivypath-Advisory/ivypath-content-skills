# IvyPath 案例模仿训练（市场实习生）

四步走：**选案 → 初改稿训练包 → 批改回稿 → 素材包**。目标是让市场实习生按「读好案例 → 看我们怎么改 → 自己改 → 被批改」的顺序，学会写我们的案例文，同时学会做 offer 图、知道该向后端要哪些服务素材。

和用户、实习生沟通一律用中文。

## 一、规则从哪里来

本 skill 只管训练：选案卡、训练包、练习任务、批改评分、素材包。怎么写案例文以 case-story-writer 为准，语言终审以 ivypath-humanize-zh 为准，两边改了规则，训练自动跟着变，这里不另抄一份。

| 要用的规则 | 读哪里（仓库 `Ivypath-Advisory/ivypath-content-skills`） |
|---|---|
| 选案：外部案例目录、授权分级、匹配层级、打分 | `case-story-writer/references/reference-cases.md` |
| 口吻、七段结构、选校课号深挖、结尾四步、句式限额 | `case-story-writer/references/house-style.md` |
| 官网长页分节、四栏短页、SEO 标题 | `case-story-writer/references/web-page.md` |
| 学员访谈体（批量篇）与每篇硬性下限 | `case-story-writer/references/structures.md` B 节 |
| 改写外部稿：只继承事实、不继承表达 | `case-story-writer/references/rewrite-mode.md` |
| offer 海报规格、打码、配图红线 | `case-story-writer/references/images.md` |
| 学员访谈 8 问、后端素材在系统哪里 | `case-story-writer/references/intake-form.md` 第八、九节 |
| 语言终审 | ivypath-humanize-zh 案例文档 |
| 自动检查 | `scripts/zh_lint.py` |

其他资料：官网长页设计稿 `/网站开发/6、网站项目库与案例库/案例库设计/README.md`（版式和图位）；口吻母本 `/网站开发/6、网站项目库与案例库/案例库/雪城_东亚研究 （已上线）/口吻母本_大阪山寺篇 copy.md`；已上线的课号深挖范例是官网 /cases/52（罗格斯 ECE → 哥大 EE）。训练包和回稿用 docx skill 生成和读取。

## 二、铁律（四步都适用）

1. **授权分级决定能不能上线**：A 授权清单、B 本团队经手可以进上线流程（B 级按改稿模式，清柚原文和图片一张不用）；C 仅培训，页眉写「培训样稿｜改编自外部公开案例｜不得发布」，不进任何对外渠道，不能说成 IvyPath 学员。分级细则见 reference-cases.md。
2. **竞品句子一律不搬**：要上线的稿和原文跑 12 字滑窗查重，命中只能是校名、项目名、数字。
3. **事实不加不改**：GPA、标化、录取学校与项目、奖学金、时间以原文或资料卡为准；课号按 house-style.md 的出处规则，训练稿一般只能查官网课程页，查不到就写【待补：课号，需查官网】。没有的写【待补】，不编。
4. **隐私**：学员称「姓的英文首字母 + 同学」；不出现真名、学号、邮箱、电话、可识别的人脸；offer 图必须打码。清柚数据表含真名，只在本地 Excel 里用。
5. **合规**：禁用语按 case-story-writer `references/quality-check.md` 第二节（zh_lint 同口径）；改写稿里不出现竞品机构名和竞品老师名（A / B 级改成「我们」和角色名，C 级改成「机构」）；A / B 级上线稿页脚保留「本文源自 IvyPath 学员真实申请案例。未经许可，请勿转载。」

## 三、第一步：选模仿案例

**输入**（任意组合）：本科学校、本科专业、目标或已录取的项目（或白皮书方向）、用途（培训 / 上线）、要几篇。

按 reference-cases.md 的匹配层级 L1–L4 和打分排序筛，输出 3–5 条选案卡。学写法优先选 PH（对应我们的 B体）；常青藤、2025 下半年以后的拓达只当反面示例；用途为「上线」时只出 A / B 级。用户在场就请他挑；没人回复就取第一名继续，并在交付时写明。

## 四、第二步：初改稿训练包（Word）

先在 Chrome 里读完原文全文，再用 docx skill 生成 `训练包_<本科简称>_<方向>_<案例编号>_<日期>.docx`，包含五部分：

1. **案例卡**：来源、授权等级、链接、学员背景、全部录取、最终去向，只写事实。
2. **原文拆解表**：原文逐段写出它的职责（导语 / 资料卡 / 动机 / 难点 / 选校 / 背景提升 / 文书 / 推荐信 / 面试 / 结果 / 寄语 / 广告），对应到我们的格式（官网长页按 web-page.md 分节；B体按 structures.md 的 Q1–Q7），标「保留 / 改写 / 删除」和原因。原文的三层选校、结尾金句一律标「删除」，并在原因里写出为什么（循环论证、模板味）。
3. **初改稿**：按 case-story-writer 写。
   - 默认出官网长页（D体）；原文是学员访谈、要练批量篇时出 B体。
   - 选校段按 house-style.md 只挖一所（最好那枚 offer，通常也是最终去向），课号和课程内容去官网查，出处写在批注里。
   - 结尾按 house-style.md 四步收住，不写金句。
   - 学员原话里的口语和英文夹杂（其实、感觉、offer、mock、AO）照留；B体的学员答问用 `::: 原话` 包起来。
   - 句式限额和豁免按 house-style.md「D体的去AI味特例」，用 zh_lint 计数。
   - 信息下限：官网长页按 web-page.md 分节表和 SKILL.md 固定模块；B体再加 structures.md B 节的每篇硬性下限。
   - 竞品机构名和老师名按授权等级替换；C 级保留原学员化名，同时加页眉水印。
   - **批注**：在 Word 批注里写「为什么这么改」，8–12 条，结构、事实、口吻、去 AI 味、合规、隐私各至少 1 条。
4. **练习任务**：给实习生 3–5 个可以检查的任务，例如：
   - 把「02 问题诊断」改成自己的话（150–250 字），三个事实点不能丢；
   - 找出初改稿里你觉得还像 AI 写的 2 句，改掉并说明理由；
   - 去入读项目的官网找 4 门课，写成课号卡片（课号 + 课名 + 一句话说明涉及什么），附官网链接；
   - 给每个录取填海报信息表（images.md 2b）；
   - 列出写这篇需要向后端要的 5 样素材，并写明在系统哪里找（intake-form.md 第九节）；
   - 写 SEO 标题和 meta description（不超过 80 字）。
5. **交回前自检清单**：事实对照、课号出处、禁用词、隐私、句式限额、栏目齐全、任务完成，逐项打勾。

交付前对初改稿跑 `python3 scripts/zh_lint.py 初改稿.docx --genre case --src 原文.txt`，然后用 SendUserFile 交付。

## 五、第三步：批改实习生回稿

**输入**：实习生交回的 Word，可能带修订和批注。

1. 取出接受修订后的全文，以及各练习任务的答案。
2. 按栏目和初改稿做对比，列出改了哪里。
3. 跑 `zh_lint.py --src 原文.txt`，检查：事实一致（数字、校名、项目、课号对照资料卡和官网）；禁用词、隐私、句式限额；12 字以上重合；三层选校、结尾金句；栏目是否齐全，信息下限是否达到。
4. 按 ivypath-humanize-zh 的规则做语感审：只指出问题、给示范改法，不整篇替实习生重写。
5. **打分（100 分）**：事实准确 20，结构与信息 20，口吻与去 AI 味 20，合规与隐私 15，原创度（查重）15，练习任务 10。每项写扣分理由，并给一处示范改法。
6. **批改报告**（Word）：总分；三处改得好的地方；三处最该改的地方（原句 → 建议）；下一篇建议重点练什么。
7. **出终稿的条件**：用途为「上线」且授权为 A / B 级时，再出一份推荐终稿，过一遍 humanize-zh 终审。C 级永远不出可发布稿。
8. **训练记录**：用户要求时，在 Dropbox 训练记录表里追加一行（实习生、案例编号、日期、分数、主要问题）。写入前先告诉用户路径，得到确认再写。实习生的改法不回填写作规则（规则只从 Daniel / Shawn 的改稿里学）。

## 六、第四步：素材包（offer 图 + 服务内容 + 向后端要素材）

### A. 原案例的 offer 图（学习用）
- 在 Chrome 里打开原文，定位图片：资料卡之后、「offer / 录取 / 捷报」附近的图，多半是录取截图或捷报海报。每张记下：第几张图；类型（offer letter 截图 / 机构捷报海报 / 邮件截图 / 学校系统截图）；显示了什么（校名、项目、奖学金、日期）；打码了哪些地方。
- 默认只给链接和位置说明。用户要截图时才截，放进训练包附录，标「外部物料·仅供内部学习」。B 级（清柚）的原文图片不截、不存。

### B. 我们的 offer 图怎么做
- 版式、打码、排名口径按 case-story-writer `references/images.md` 2b 节（官网「OFFER捷报」海报）。
- 示范：给本案例每个 offer 填一张海报信息表，再附一张空白表给实习生用于我们的学员。

### C. 服务内容，以及向后端要什么
- **服务动作表**：把原文里的服务动作抽出来，列「阶段｜原文做了什么｜对应我们长页哪一栏｜我们自己的案例需要什么证据」。阶段包括规划、选校、背景提升、文书、推荐信、网申、面试、选 offer、奖学金。
- **素材在系统哪里、找谁**：按 intake-form.md 第九节的表，问后端时直接说位置。要学员原话时，发 intake-form.md 第八节的学员访谈 8 问。
- **消息草稿**：再写一段能直接发给后端的消息，写明学员化名、要哪几样、文件格式、打码要求和截止时间。

## 七、交付与命名

- **格式**：训练包和批改报告都用 Word，用 SendUserFile 交付。要放进 Dropbox 时，先说清路径，得到用户同意再写。
- **命名**：
  - `训练包_<本科简称>_<方向>_<案例编号>_<日期>.docx`
  - `批改_<实习生>_<案例编号>_<日期>.docx`
  - `素材清单_<学员化名>_<日期>.md`
- **给用户的回复**只写四件事：选了哪篇和为什么、交付了什么、实习生下一步的任务、还缺哪些素材。不复述文件内容。
